## 摘要
智能体的使用正转向编程和科学发现等长时程任务，其中终端任务尤为重要。我们提出 T1，一个总参数量为 122B 的混合专家模型，通过强化学习训练，可在云沙箱中操作真实 shell，每个任务最多进行 300+ 轮工具调用，并通过执行每个任务自身的验证器获得奖励。我们提供了一套完整的方案：首先，采用激进的预热启动以稳定 actor-critic 训练，并使用稠密过程奖励，依据通过验证器的绝对数量对轨迹进行评分。其次，通过 TITO 构造实现稳定优化，在训练时使用精确采样的 token 标识符并在轮次边界进行漂移修复，以及 rollout 路由重放，记录采样器在每个 MoE 层的逐 token 专家选择，并在训练期间重放这些选择。第三，完全分布外的训练语料：与 Terminal-Bench 2.1 不相交的隔离种子和合成任务，确保性能提升反映的是真实的能力迁移，而非对基准的过拟合。TITO 和 R3 共同将训练到推理的对数概率差异从 0.021 降至 0.013，并在损失区域实现完全对齐的零 token 漂移。在 Terminal-Bench 2.1 上，我们的后训练流程将初始基础模型从 43.8% 提升至 T1 的 64.0% 解决率。在 Long-Horizon Terminal Bench 上，T1 达到 27.9%，并超越 GPT-5.4 和 GLM-5.1。

## Abstract
Agent usage is shifting toward long-horizon tasks such as coding and scientific discovery, among which terminal tasks are especially important. We introduce T1, a Mixture-of-Experts model of 122B total trained with reinforcement learning, operating a real shell in a cloud sandbox for up to 300+ tool-call turns per task, rewarded by executing each task's own verifier. We provide a comprehensive recipe: First, an aggressively warm-started to stabilize actor-critic training, with a dense process reward scoring trajectories by the absolute number of passing verifiers. Second, stable optimization through TITO construction, training on the exact sampled token identifiers with drift repair at turn boundaries, and rollout routing replay, recording the sampler's per-token expert choices at every MoE layer and replaying them during training. Third, fully out-of-distribution training corpus: isolated seeds and synthesized tasks disjoint from Terminal-Bench 2.1 ensures gains reflect genuine capability transfer over benchmark overfitting. Together, TITO and R3 cut the training-to-inference log-probability difference from 0.021 to 0.013, with exactly aligned zero token drift in the loss region. On Terminal-Bench 2.1, our post-train pipeline raises initial base model from 43.8% to T1 with 64.0% resolved. On Long-Horizon Terminal Bench, T1 reaches 27.9% and surpasses GPT-5.4 and GLM-5.1.

## 1. 核心问题与研究动机

- **背景**：LLM 智能体正从单轮代码补全、对话辅助转向自主长时程执行，其中 Linux 终端是最严苛的测试场——它把抽象规划与不可逆副作用绑定，要求环境理解、任务分解与从部分失败中精确恢复的能力在远超常规推理基准的时间尺度上持续保持。
- **核心问题**：在真实 shell 中做数百轮工具调用的强化学习，面临两大主导性困难：
  - **稀疏 MoE 的训练-推理一致性**：专家参数占 116.0B/121.4B，每 token 通过离散路由激活 8/256 个专家。推理与训练引擎的微小数值差异会翻转专家选择，使梯度流向与生成行为的参数不一致；多轮 harness 还会在每个轮次边界扰动 token 序列。
  - **执行奖励的稀疏性**：一个 rollout 批次耗费数百沙箱小时，而二元结果只返回 1 bit/轨迹；作者首个二元奖励训练从未超过监督基线。
- **整体含义**：终端性能不是终点，而是迈向在关键基础设施上可靠行动的智能体的一步。论文主张"基于真实执行而非学习偏好模型的奖励，必须被证明能在大规模前沿稳定优化"。

## 2. 方法论

### 2.1 整体框架（异步 PPO + 三组件流水线）

- 训练后端与推理副本运行在不相交的加速器上，基于 slime 框架，将第 t 步训练与第 t+1 步生成流水化以隐藏延迟。
- 每个任务自包含：资源限制、长时程指令、环境镜像、**held-out 验证器**（逐断言报告）、参考解。
- 训练器每步**先更新 critic 再更新 actor**（critic 的更新前值锚定优势估计）；权重每步发布一次，发布前静默生成，使 off-policy 程度恰为一步。

### 2.2 TITO：Token-In-Token-Out（token 保真）

- **问题**：harness 把每条 assistant 消息持久化为文本并在每轮重新渲染，`enc(dec(a_i))` 不是恒等映射；编码规范化、模板裁剪推理、工具调用重序列化都会造成 token 漂移。
- **机制**：让训练器消费采样器实际发出的 token 标识符，要求 `T_i` 在每个边界都是 `p_{i+1}` 的 bit-exact 前缀。轮次边界按由强到弱的四级层次修复：
  1. **strict**（精确前缀，取残差后缀）；
  2. **normalized**（在 97×17 有限网格上有界修复）；
  3. **retokenized**（回退到文本空间相等，永不使用 `ã_i`，只追加采样的 `a_i`）；
  4. **split**（打开新 chunk）。
- **验证**：在 1,402 个样本上，损失区域内漂移率为 **0.0000%**。

### 2.3 R3：Rollout Routing Replay（路由保真）

- **机制**：记录推理时每个 MoE 层的专家选择掩码 `I^{r,ℓ}_j`，训练前向传播时复用它做 TopK 选择，但**归一化仍在实时 logits 上进行**：
  - `g^{ℓ}_{j,e} = exp([s^ℓ_j(θ_t)]_e) / Σ_{e'∈I^{r,ℓ}_j} exp([s^ℓ_j(θ_t)]_{e'})`，仅对记录专家求和。
- **双重目的**：对齐训练与推理（梯度到达的专家恰是产生样本的专家）；保留梯度路径（router 仍可训练，计算图不变）。
- **成本**：每 token 1.5 KiB（48 MiB/33k token 轨迹），rollout 开销 <3%，无额外算术。
- **对齐细节**：掩码随 KV cache 缓存并在前缀命中时复用；在修复边界上，仅当 `m_{j+1}=0`（无梯度）时才用邻居记录替换，否则报错中止。

### 2.4 密集验证奖励

- **定义**：`r = P/S`，`S=20`，其中 `P` 为通过断言数。**用绝对通过数而非通过比例**，因为难任务断言更多，绝对数能反映混合批次中真实进展。
- **固定全局尺度**：S=20 取自 T1-15k 断言分布约 90 分位（中位数 4，最大约 35）；固定分母避免逐批最大值导致 critic 回归目标漂移。
- **回退**：逐断言报告缺失/不可解析时回退到二元终局结果，保证已解任务不会得零分。
- **信用分配**：标量置于最后响应 token，`γ=λ=1` 的 GAE 把信用反向传播到整个轨迹；奖励**不做归一化**（每任务一条轨迹，无组统计量），critic 是唯一基线。

### 2.5 Critic 预热与稳定性

- **Critic Warm-Up**：先在 TMax-15k 上训练一个 epoch 的价值网络（仅保存 critic 权重），再开始任何策略步。
- **学习率**：critic 1.5×10⁻⁵ vs actor 1.0×10⁻⁶（约 30× 比例）。
- **EV（解释方差）**：冷启动从 **−33.6** 开始且 58 步中 30 步为负；预热后稳定在 **0.71–0.86**，从不转负。
- **有意省略的可选项**：KL 惩罚（冻结参考路由自选会不公正地惩罚策略）、MoE 负载均衡系数设为 0（均衡压力要求 router 重分配，恰与 replay 要求相悖）。
- **过采样**：batch 560 启动、接纳前 512 完成、取消长尾，限定步时间但引入对最长轨迹的轻微偏置。

### 2.6 关键量化结果

- TITO + R3 将训练-推理对数概率差从 **0.021 降至 0.013**，损失区域零 token 漂移。
- 基础设施：同驻 122B actor-critic 需各自在 95 GiB 内放下；容量模型证明**专家优化器状态与分片方案无关**，只能靠扩大设备数 G 降低；context parallelism 原生分片循环算子，激活峰值在 κ∈{2,4,8} 下降至约 1/2、1/4、1/8。

- **长时程迁移

- **长时程迁移**：在 LHTB 上 T1 获得最高平均奖励，且随轮次预算增加持续增益，说明其优势不是靠"更早撞对答案"，而是靠维持长程一致性；TBH 上同样领先，表明增益可迁移到未见的更难分布。

- **消融性证据（间接）**：R3 关闭时训练-推理 log-prob 差回升且训练不稳定；TITO 关闭时轮次边界出现 token 漂移并损害收敛；27B 路径实验显示学习率比例过小（10×）时 critic 欠拟合、过大（30×）时策略更新噪声放大，20× 附近最优，佐证了稳定性设计的重要性。

- **奖励消融不彻底**：如第 5 节所述，二元与密集奖励的对比是 campaign 级联变，无法隔离奖励、数据池、初始化与 R3 的独立贡献；作者将其列为最重要的后续工作。
- **算力报告缺失**：未披露 GPU 型号/数量/总时长，削弱了可复现性与成本可比性。
- **基础设施耦合**：TITO 与 R3 均深度依赖特定推理/训练引擎（SGLang + Megatron-Core）的实现细节，迁移到其他栈需要重新实现边界修复与掩码缓存逻辑。
- **任务分布偏斜**：T1-15k 中调试（1.3%）、性能可观测性（1.0%）、文档（0.6%）占比极低，可能限制模型在这些子领域的泛化。
- **单 harness 评估**：主结果基于 Terminus-2，作者自己也指出 harness 会显著影响分数，跨 harness 可比性有限。
- **偏置引入**：过采样导致对最长轨迹的轻微偏置，可能低估极长时程任务的真实难度。

## 8. 启示与展望

- **对 RL 基础设施**：论文的核心方法论贡献——TITO（token 保真）与 R3（路由保真）——把"训练-推理一致性"从工程细节提升为一等公民。二者成本极低（TITO 无额外开销，R3 <3% rollout 开销、1.5 KiB/token），却直接决定稀疏 MoE 能否被稳定优化，具有可复用的范式价值。
- **对奖励设计**：用绝对通过断言数（而非比例）并固定全局尺度 S=20，是一种在混合难度批次中兼顾"真实进展"与"critic 目标稳定"的实用折中，可迁移到其他多断言验证场景。
- **对长时程智能体**：结果支持"真实执行奖励 + 保真优化"可以在大规模前沿稳定工作，反驳了"必须依赖学习偏好模型"的假设。
- **后续方向**：(1) 单轴奖励消融；(2) 降低对特定引擎的耦合；(3) 扩展低占比子领域（调试、性能）的任务合成；(4) 探索更高效的长上下文状态保持机制以缓解压缩丢失。

## 9. 总体评价

论文在**问题选择**（终端长时程 RL 的真实痛点）、**方法论**（TITO + R3 + 密集验证奖励 + critic 预热的组合拳）、**工程严谨性**（漂移率 0.0000%、EV 稳定性度量）上均属高水准，主结果以 10B 激活参数逼近 Claude Opus 4.7 尤其有说服力。主要短板在于**奖励消融不彻底**与**算力报告缺失**，前者影响因果归因，后者影响可复现性。总体而言，这是一篇兼具系统深度与实证强度的前沿工作，其"训练-推理保真"思路对后续大规模智能体 RL 具有明确的指导意义。
