## 摘要
扩大交互视界——即每个回合中与环境交互的最大次数——能够提升 LLM 智能体在长时程任务上的表现，而逐步扩展视界的课程式方法优于固定视界的方法。然而，现有调度策略是开环的：它们单调递增视界直至人工指定的最大值，缺乏检测进一步扩展何时不再有益的机制。我们提出有效交互前沿假设：存在一个动态边界，超过该边界后，额外的交互带来递减的回报，而成本却线性增长。随后我们提出 Elastic Horizon，一种闭环控制器，通过成功轨迹长度的第 90 百分位数来跟踪该边界。在 AppWorld 与 BFCL 上，固定视界扫描揭示出明显的饱和平台；Elastic Horizon 能够从容量不足与容量过高的初始设置出发，将视界稳定在饱和区间内，在 7B 与 14B 骨干模型上取得最佳成功率，并最多节省 25% 的每步轨迹 token。我们的工作将范式从如何扩展交互视界转向何时停止扩展。

## Abstract
Scaling the interaction horizon-the maximum number of environment interactions per episode-improves LLM agents on long-horizon tasks, and curriculum-based methods that progressively expand the horizon outperform fixed-horizon alternatives. However, existing schedules are open-loop: they monotonically increase the horizon until a manually specified maximum, with no mechanism to detect when further expansion stops helping. We propose the effective interaction frontier hypothesis: a dynamic boundary beyond which additional interactions yield diminishing returns while cost grows linearly. We then introduce Elastic Horizon, a closed-loop controller that tracks this boundary via the 90th percentile of successful trajectory lengths. On AppWorld and BFCL, fixed-horizon sweeps reveal clear saturation plateaus; Elastic Horizon stabilizes the horizon inside the saturation band from both under- and over-capacity initializations, attains the best success rates across 7B and 14B backbones, and saves up to 25% of per-step trajectory tokens. Our work shifts the paradigm from how to scale interaction horizons to when to stop scaling.

# Elastic Horizon 论文深度总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：在部分可观测环境中，LLM 智能体需要通过多轮交互（工具调用、API 请求）收集信息以完成长时程任务。近期研究表明，扩大**交互视界（interaction horizon，即每回合最大环境交互次数 K）**能显著提升长时程任务表现。
- **现有做法的共性缺陷**：以 ScalingInter-RL（线性递增）与 TTI（乘性递增）为代表的课程式方法均为**开环调度**——视界仅按训练步数 t 的预设函数单调增长，直至人工指定的上限 K_max，**没有任何机制判断继续扩展是否还有收益**。
- **被挑战的隐含假设**：这些方法默认"性能随视界单调提升"。本文用固定视界扫描实验证明该假设不成立：性能在达到某阈值后进入平台期，而计算成本（与轨迹长度成正比）持续线性增长。
- **核心假设**：提出**有效交互前沿（effective interaction frontier）H\***——一个由任务复杂度与智能体能力共同决定、且随训练动态变化的边界，超过它后额外交互带来边际收益递减。
- **范式转变**：从"**如何扩展交互视界**"转向"**何时停止扩展**"。

## 2. 方法论

### 核心思想
用一个**闭环控制器**从智能体自身"已证明的能力"（成功轨迹长度分布）中反推 H\*，双向（扩张/收缩）调节下一轮 rollout 的视界，使其自动收敛到饱和带内。

### 三条设计需求
- **R1 能力驱动信号**：调节依据是智能体的实际表现，而非训练步数。
- **R2 稳健估计**：对低效探索产生的异常长轨迹鲁棒，同时对真实能力变化敏感。
- **R3 双向适应**：既能扩张也能收缩（单调调度无法从"容量过高"一侧收敛）。

### 关键技术细节与流程
1. **成功缓冲池 B**：仅收集终止奖励 r(τ)=1 的轨迹长度，FIFO 容量 N=100，保证估计反映**当前**而非历史能力。
2. **能力边界估计（P90）**：
   - B̂_t = P90(B_t)，即成功轨迹长度的第 90 百分位。
   - 选 P90 的权衡：均值/P50 低估能力上限、导致视界过于保守；Max 受单个异常轨迹影响、方差大。P90 兼顾"接近能力上限"与"过滤前 10% 离群值"。序统计理论支持：重尾分布下样本最大值方差发散（Pareto 指数 α<2 时），而分位数方差为 O(1/n)。
3. **探索余量（headroom）**：K^target_t = B̂_t + ∆，∆=10，为尝试稍难任务预留空间（类比"最近发展区"）。
4. **EMA 平滑**：
   - K_{t+1} = (1−α)·K_t + α·clip(K^target_t, K_min, K_max)，α=0.1。
   - 小 α 稳定但适应慢，大 α 响应快但易震荡。
5. **冷启动处理**：当 |B| < N_min（=20）时保持当前视界不变，避免早期估计不可靠导致的剧烈波动。
6. **算法主循环（Algorithm 1/2）**：按当前 K 采样轨迹 → GRPO 更新策略 → 将成功轨迹长度写入 FIFO 缓冲 → 若缓冲足够则计算 P90、加余量、EMA 更新得到 K_{t+1} → 作为下一轮 rollout 视界（闭环反馈）。
7. **开销**：缓冲维护、分位数计算与 EMA 更新均为 O(N) 操作，控制器额外开销 <0.1%。
8. **理论讨论（附录 B）**：给出 P90 的重尾稳健性论证与 EMA 在**平稳目标**下的几何收敛界，但明确声明这只是启发式控制器的经验性支撑，不构成 H\* 的闭式保证。

## 3. 实验设计

### 环境 / Benchmark
- **AppWorld**：高保真执行环境，模拟 9 个日常应用（Amazon、Venmo、Spotify、Gmail 等）与 457 个 API，需跨应用协调调用；报告任务目标完成率。
- **BFCL v3**：多轮函数调用基准，覆盖 8 个 API 域，多轮划分含 1,000 条需状态化交互的测试用例。
- 两者均使用二值稀疏奖励，最大轨迹长度限制为 50 步。

### 对比方法
- **零样本基线**：Qwen2.5-7B / 14B / 32B、Qwen3-235B-A22B。
- **固定视界 GRPO**：K=15（保守）与 K=50（最大）。
- **TTI**（Shen et al., 2025）：乘性调度 15→20→30→50，每阶段 50 步。
- **ScalingInter**（Xi et al., 2025）：线性调度，δ=0.2/步，从 K_min=10 到 K_max=50。
- **固定视界扫描**：K 从 10 扫到 80（AppWorld）/ 60（BFCL），用于验证饱和现象。

### 训练配置
- 骨干：Qwen2.5-7B 与 Qwen2.5-14B；GRPO，KL 系数 0，200 训练步，batch size 16，学习率 1e-6；基于 AgentEvolver 框架；指标为 mean@8。
- Elastic Horizon 超参：K₀=15，α=0.1，∆=10，N=100，N_min=20，K_min=5，K_max=50。

### 消融与附加实验
- **百分位选择**：Mean / P50 / P90 / P95 / Max（两基准）。
- **余量 ∆**：0 / 5 / 10 / 15 / 20。
- **EMA 系数 α**：0.1 / 0.2 / 1.0。
- **效率分析**：每步 token 消耗曲线、累积 token 与成功率关系、BFCL 每步 token。
- **统计显著性**：7B 配置 3 个随机种子。

## 4. 资源与算力

- 论文说明实验在**单个计算节点、每次训练使用 8 个 AI 加速设备**上完成，但**未给出具体 GPU 型号**。

## 5. 实验数量与充分性

- **规模**：2 个 benchmark × 2 个骨干（7B/14B）× 多类基线（固定视界 2 种 + 2 种开环课程 + 4 个零样本模型），加上固定视界扫描（约 8 个 K 值 × 2 基准）与 3 组消融，实验矩阵较为完整。
- **客观性/公平性**：
  - 基线在相同训练步数、batch、学习率下比较，TTI 与保守基线共享初始视界 K=15，调度上限统一为 50。
  - 先独立验证"饱和现象"（RQ1）再验证控制器收敛（RQ2），逻辑链条自洽，避免了"结果导向"的循环论证。
  - 7B 报告 3 种子均值±标准差，并对训练不稳定（GRPO K=50 在 BFCL 上方差 ±4.52）做了显式标注。
- **不充分之处**：
  - **14B 无多种子统计**，最强结果（AppWorld Best@8=90.42%）缺乏方差支撑。
  - 消融主要只在 AppWorld（且多为 Step 200 单点）上进行，跨 benchmark 的消融覆盖有限。
  - 未与"自适应测试时预算"方法（如 BATS）做端到端对比，仅做了定位层面的讨论。

## 6. 主要结论与发现

1. **视界饱和确实存在**：AppWorld 上 K∈[30,60]、BFCL 上 K∈[20,50] 收敛到同一奖励平台，而每步成本相差约 2 倍；H\* 随任务不同而不同。
2. **自动前沿发现可行**：Elastic Horizon 从 K₀=10（容量不足）与 K₀=50（容量过高）两个极端初始化出发，均能稳定落入 RQ1 识别的饱和带（图示 H\*≈33），且**从不触及 K_max=50**；开环调度则必然单调升至 50。
3. **性能最优**：在 AppWorld 与 BFCL、7B 与 14B 四个组合上均取得最佳成功率（如 AppWorld 14B Best@8=90.42%，BFCL 7B Mean@8=71.62%）。训练后的 7B 模型在 AppWorld 上超过零样本 Qwen2.5-32B（39.06%）与 Qwen3-235B-A22B（33.85%）。
4. **固定视界困境**：K=50 在 AppWorld 有帮助，但在 BFCL 反而导致训练不稳定，印证超过 H\* 会损害学习效率。
5. **效率收益**：AppWorld 上每步轨迹 token 在中训练阶段（step≈140）较 GRPO 减少 **25%**，收敛后仍少 **11%**；在 AppWorld 7B 上达到 SR=50% 时累积 token 减少 **28%**（36.28M vs 50.21M）。

## 7. 优点

- **问题定位精准**：指出开环课程"只增不减、无法判断何时停止"的结构性缺陷，把交互预算从"超参数"重新定义为"可由训练过程测量的量"。
- **方法极简且可插拔**：仅需一个整数缓冲、一次分位数与一次 EMA，<0.1% 开销，不修改策略更新路径，可叠加在任意 agentic RL 流程上。
- **信号选择有依据**：用"成功轨迹长度分布"作为能力代理，比训练损失或奖励统计更能区分"能力"与"任务难度"；P90 的选择有重尾分布下的序统计直觉支撑。
- **双向收敛是真正的差异化卖点**：单调调度在原理上无法从过容量初始化收敛，本文用双端初始化实验直接验证。
- **实证链条完整**：先做固定视界扫描确认饱和带（RQ1），再验证控制器落入该带（RQ2），最后做性能与效率对比（RQ3），并配以分位数、余量、EMA 三组消融与 7B 多种子方差。
- **实用与绿色 AI 价值**：在小模型（7B）上逼近/超越大模型零样本表现，并显著降低训练 token 消耗。

## 8. 不足与局限

- **冷启动依赖成功样本**：早期或极难任务上成功轨迹稀少，P90 估计不可靠；当前"缓冲未满则冻结视界"的策略保守，可能延迟适应。作者建议未来可用部分进展信号或全部轨迹分布。
- **单一全局视界**：所有任务共享一个 K_t，对难度方差大的任务分布次优——简单任务被浪费预算，困难任务仍被截断；未做实例级或难度条件化分配。
- **P90 属经验启发式**：缺乏第一性原理推导，P75–P95 区间内表现稳健但最优百分位可能任务相关；∆ 的最优值同样无法从理论导出（且消融呈非单调）。
-

- **冻结策略在难度非平稳时可能滞后**：缓冲未满（|B|<20）即冻结视界，若训练中途引入更难任务或课程切换，成功样本重新稀疏，控制器会"锁死"在当前 K 上，缺乏应对分布漂移的机制。
- **超参数未做系统敏感性分析**：K_min、K_max、N、N_min 均直接给定，其中 K_max 仍是人工先验上限，某种意义上把"何时停止"的问题部分转移为"上限设多少"的问题（尽管实验显示实际 H\* 远低于 K_max，未触及上限）。
- **仅在二值稀疏奖励下验证**：方法依赖"成功轨迹长度"这一信号，若任务使用稠密/部分奖励或存在多级成功标准（如 BFCL 的部分正确），P90 的定义与缓冲池的筛选准则需重新设计，泛化性未知。
- **未验证迁移与持续学习**：所有评估都在同分布测试集上，未考察控制器学到的视界是否能跨任务族迁移，或在任务分布随时间变化时的稳定性。
- **规模上限有限**：最大仅验证到 14B，未验证更大模型下 H\* 的移动规律（能力越强，H\* 是否单调下降、控制器是否仍稳健），也未做 32B 以上的训练实验。
- **与测试时预算自适应的关系未厘清**：文中讨论定位差异，但未提供端到端对比实验，无法直接说明训练期闭环控制相对推理期预算分配的优势边界。

- **概念贡献大于方法贡献**：本文最核心的产出不是控制器本身，而是把"有效交互前沿 H\*"从一个模糊直觉形式化为**可由成功轨迹分布测量的动态量**，为后续工作提供了可操作的分析工具与评测视角。
